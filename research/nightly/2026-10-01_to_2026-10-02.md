## 18:00 — False-positive rejection via geometry-conditioned DINO evidence

**Question.** Can DINO false positives be reduced without sacrificing sparse-view recall or adding a heavy model?

**Code fact.** The current detector compares rendered-old and observed-new DINOv2 intermediate features with per-location cosine similarity, applies one threshold, and optionally dilates the binary mask. It does not explicitly test whether low similarity comes from physical change versus depth-boundary/occlusion/render misregistration. Multiview voting can reject random errors, but repeated boundary errors can survive.

**Literature.** CL-Splats uses DINOv2 masks, dilation, 3D voting, and localized optimization. Its ablation favors voting over an all-view requirement, so simply making min-positive-views very strict is not an attractive sparse-view fix. The paper also states that global illumination changes remain a limitation (Ackermann et al., ICCV 2025, arXiv:2506.21117).

**Hypothesis H1 (unverified).** A meaningful subset of false positives is concentrated at pixels that are geometrically unreliable for rendered-old versus observed-new comparison: depth discontinuities, occlusion/disocclusion boundaries, or small pose/render mismatch.

**Proposed diagnostic.** Log soft DINO evidence s_dino = clamp((tau-cosine)/margin,0,1) and rendered-depth edge reliability r_edge = exp(-abs(grad(D_render))/sigma). Initially do not reject edge pixels. Test whether FP pixels have larger depth-gradient magnitude than TP pixels. If separation exists, test soft positive evidence e_pos = s_dino * r_edge instead of equal binary votes.

**Quantitative test.** On Blender before/after data, record DINO cosine, current decision, rendered-depth gradient, distance to depth discontinuity, and changed/unchanged reference label. Compare current DINO, hard edge rejection, and soft edge weighting at matched recall. Metrics: pixel precision/recall/F1/IoU, downstream active-Gaussian precision/recall, changed-region PSNR, and latency.

**Falsification.** Reject H1 if FP and TP depth-gradient distributions overlap strongly and geometry confidence cannot improve precision at matched recall.

**Why before threshold sweeps.** Threshold/dilation/min-positive sweeps only move the operating point. This diagnostic tests a causal explanation and costs little because rendered depth already exists.

**Coverage/Convergence implication.** If precision improves at maintained recall, part of the apparent sparse-view problem may be evidence quality rather than viewpoint count. If not, view geometry remains a stronger candidate. Coverage and Convergence remain working hypotheses.

**Execution status.** No remote GPU experiment was executed by this automation. No behavior-changing source patch was made in this iteration.

**Next.** Instrument FP/TP DINO cosine and rendered-depth-gradient distributions on the test branch; only then consider confidence-weighted multiview voting.


## 19:00 — Depth lifting bottleneck: alignment support, not depth-network accuracy, may dominate sparse-view failure

**Question.** In the <=10-view regime, is the Depth Anything V2 stage failing mainly because monocular depth is inaccurate, or because CL-Splats cannot robustly align relative depth to the existing GS metric frame from the available pixels?

**Measured evidence.** In the user's earlier CL-Splats run, depth alignment failed for 58/75 views. This is unusually high even with many input views, so "more views" alone cannot be assumed to solve lifting. The 5-view deployment target makes per-view alignment failure much more consequential: losing 2–3 views can collapse multiview support even if DINO change detection itself is correct.

**Code/config facts.** Current configuration uses `depth-anything/Depth-Anything-V2-Small-hf`; downstream lifting then applies k-NN/local-radius/depth-consistency gates. The inspected lifter path from the prior debugging session calls `align_relative_depth(mono, rendered_depth, change_mask, min_pixels=200)`. Thus metricization is a separate estimation problem after monocular inference. This matters because DA-V2's general relative-depth model is explicitly scale/shift ambiguous; improving the network does not automatically remove alignment failure.

**Literature.** Depth Anything V2 (Yang et al., 2024, arXiv:2406.09414) emphasizes robust relative depth and provides separately fine-tuned metric models. Depth Pro (Bochkovskii et al., 2024, arXiv:2410.02073) predicts metric depth directly and reports ~0.3 s for a 2.25-MP map on its reference GPU, showing that metric monocular depth can be fast, but domain transfer remains an assumption. UniDepthV2 (Piccinelli et al., 2025, arXiv:2502.20110) predicts metric 3D and an uncertainty output, which is attractive for confidence-weighted lifting but is a heavier replacement. Most directly relevant, Reliability-Aware Monocular Depth Supervision for Sparse-View Neural Reconstruction (Chu et al., 2026, arXiv:2607.02554) aligns DA-V2 per-image scale/shift to sparse metric anchors and finds that selectively using reliable depth regions matters more than globally supervising all pixels; this supports testing anchor quality before replacing DA-V2.

**Causal hypothesis H2 (unverified).** A major part of sparse-view lifting failure is ill-conditioned scale/shift estimation caused by too few, too spatially concentrated, or contaminated alignment pixels, rather than DA-V2 inference error itself. If the alignment support is selected from/around a change mask, changed/occluded pixels can further contaminate the fit.

For relative prediction \(d_r(p)\) and rendered metric depth \(d_g(p)\), estimate
\[
(a^*,b^*)=\arg\min_{a,b}\sum_{p\in A} w_p\,\rho(a d_r(p)+b-d_g(p)),
\]
where \(A\) should be reliable unchanged/visible anchors, \(\rho\) is a robust loss (Huber/Tukey), and \(w_p\) downweights depth edges, low rendered opacity, suspected change, and high monocular uncertainty. This is preferable to treating every available alignment pixel equally.

**Important distinction from the 18:00 hypothesis.** The 18:00 run asked whether geometry uncertainty explains DINO false positives. H2 instead asks whether geometry uncertainty corrupts *metric depth alignment after detection*. Both can be true, but they are experimentally separable.

**Minimal diagnostic before changing models.** For every view log: number of candidate anchors; number/inlier ratio after robust fit; spatial coverage of anchors (occupied image-grid cells); fitted scale \(a\), shift \(b\); residual median/MAD and p90; failure reason; and whether the view later contributes positive/negative 3D votes. Compare successful versus failed alignment views. Also recompute alignment with (A) current anchors, (B) unchanged-mask-only anchors, (C) unchanged + depth-edge exclusion, and (D) robust IRLS/RANSAC-style fit.

**Falsifiable prediction.** If H2 is correct, alignment success and downstream active-Gaussian recall should correlate more strongly with anchor inlier count/spatial spread and residual MAD than with raw image count. Robust unchanged-region alignment should recover a substantial fraction of currently skipped views without replacing DA-V2.

**Failure criterion.** Abandon H2 as a primary bottleneck if failed views already have abundant, spatially distributed low-residual anchors, or if robust alignment increases accepted views but does not improve active-Gaussian precision/recall or changed-region reconstruction. In that case test monocular-depth domain error / occlusion geometry directly, or benchmark a metric model such as Depth Pro/UniDepthV2.

**Latency.** Robust affine fitting over <=1024 anchors is negligible relative to DA-V2 inference (typically milliseconds on GPU/CPU for IRLS/RANSAC-scale operations). Reliability masks from existing rendered depth/opacity are also cheap. Therefore this intervention is compatible with the <=10 s target and is preferable as the next test to swapping in a heavier depth foundation model.

**License/deployment note.** Do not switch models on paper performance alone; verify code/weight licenses separately before any industrial recommendation. This iteration makes no commercial-use claim for Depth Pro or UniDepthV2.

**Execution status.** No Spark/GPU experiment was executed by this automation. No behavior-changing source patch was made. The proposed diagnostic is unexecuted.

**Next experiment.** Instrument alignment conditioning and failure reasons first. If H2 survives, implement robust unchanged-region scale/shift fitting and compare 5-view active-set recall, skipped-view count, changed-region PSNR/SSIM/LPIPS, prepare time, and total latency against the current aligner. This should precede a DA-V2→metric-depth model replacement.


## 20:00 — Multiview voting audit: `visible_views` is not true visibility and can be double-counted

**Question.** Before tuning `min_visible_views`, `min_positive_views`, `min_positive_ratio`, and `final_thresh`, do those statistics represent the intended probabilistic events in the current implementation?

**Code facts (test branch).** In `DepthAnythingLifter.lift()`, `visible_views[g]` is incremented when a Gaussian appears in the unique k-NN set of sampled *positive* pixels, and incremented again when it appears in the unique k-NN set of sampled *negative* pixels. Therefore it is not geometric camera visibility. The same Gaussian can receive two visibility increments from one camera if it is touched by both sampled sets. In contrast, `positive_views` is incremented once per camera only for Gaussians surviving the positive local-radius **and depth-consistency** gates. The negative path applies the local-radius gate but does **not** apply the analogous depth-consistency/occlusion gate before accumulating `neg_score` and visibility. Finally,
\[
r_g = \frac{N^+_g}{N^{vis}_g},\qquad
keep_g=[N^{vis}_g\ge m_v]\land[N^+_g\ge m_p]\land[N^{seed}_g\ge m_s]\land[r_g\ge r_{min}],
\]
then
\[
S_g=\frac{\lambda_s E^+_g}{\lambda_s E^+_g+\lambda_n E^-_g+\epsilon},\qquad changed_g=[keep_g]\land[S_g>\tau_f].
\]
Because `Nvis` can exceed the number of valid cameras and negative evidence can come from depth-inconsistent samples, `r_g` is not currently interpretable as “fraction of visible views that see change.”

**Important consequence.** With five valid views, a Gaussian could in principle accumulate up to ten `visible_views` increments if both positive and negative sampled sets touch it in every view. Thus the configured `min_positive_ratio=0.3` does not have the semantics its name suggests. Sparse-view recall/precision may be affected by implementation semantics before any genuine “coverage” limitation. This is a stronger confounder than ordinary threshold choice and should be fixed/audited before drawing causal conclusions from a threshold sweep.

**Connection to 18:00 and 19:00.** The 18:00 hypothesis concerned DINO FP quality; the 19:00 hypothesis concerned depth-alignment failures. This audit adds a third, downstream confounder: even with perfect DINO masks and successful metric depth alignment, evidence aggregation can misrepresent visibility and can inject occlusion-inconsistent negative evidence. Therefore low 5-view active-set recall cannot yet be uniquely attributed to viewpoint coverage.

**Literature.** CL-Splats (Ackermann et al., ICCV 2025) explicitly motivates 3D multiview voting and reports that its voting strategy is preferable to an all-view requirement, reinforcing that view-level evidence semantics matter. GaussianUpdate (Zeng et al., ICCV 2025, arXiv:2508.08867) independently emphasizes visibility-aware continual updating. 3DGS-CD (Matsushima et al., RA-L 2025) associates/fuses 2D changes across views and demonstrates sparse post-change detection, including one-view cases, again suggesting that “number of input images” and “correctly modeled visibility/evidence” should be separated experimentally. These papers do not by themselves prove the present implementation is wrong; the code audit above is the direct evidence.

**Hypothesis H3 (falsifiable).** Correct per-camera geometric visibility plus symmetric depth/occlusion gating for positive and negative evidence will improve active-Gaussian precision/recall at <=10 views more than tuning the current ratio thresholds, because the current denominator and negative evidence are biased.

**Minimal replacement semantics.** For each camera (v), project Gaussian mean (g) and define true visibility
\[
V_{gv}=1[z_{gv}>0]\,1[(u_{gv},v_{gv})\in image]\,1[|z_{gv}-D^{old}_v(u,v)|<\tau_z],
\]
optionally strengthened with rasterizer contribution/alpha. Define a single per-view change observation (C_{gv}) only when (V_{gv}=1), then accumulate
\[
N^{vis}_g=\sum_v V_{gv},\quad N^+_g=\sum_v V_{gv}C_{gv}.
\]
Each camera contributes at most one visibility count per Gaussian. Negative evidence is allowed only for visible, depth-consistent Gaussians. A later confidence-weighted version can replace (C_{gv}\in\{0,1\}) with calibrated DINO/depth confidence, but the binary semantics should be repaired first.

**Quantitative test.** On fixed 5-view seeds, compare: A=current aggregation; B=deduplicated per-view touched-set only; C=true projected visibility + symmetric depth gate; D=C plus confidence weighting. Hold DINO masks, DA-V2 depth, selected views, and optimization settings fixed. Before optimization measure active-mask precision/recall/F1/IoU against the 50-view reference *and*, where synthetic GT permits, true changed-region support. Also log max/mean `visible_views`, count of Gaussians with `visible_views > valid_views`, positive-ratio histograms, negative candidates rejected by depth consistency, active count, and lifting latency. Then run identical 100-iteration local optimization and compare changed-region PSNR/SSIM/LPIPS.

**Falsification.** Reject H3 as a major bottleneck if (i) `visible_views > valid_views` is essentially absent, (ii) depth-consistency removes negligible negative evidence, and (iii) B/C do not materially improve active-mask F1 or changed-region quality across seeds. If so, return priority to actual geometric coverage/view selection or alignment.

**Latency.** True visibility need not add a network. Projection of N local candidate Gaussians into <=10 cameras is a batched matrix operation; rendered old depth already exists. Restricting to candidate Gaussians should keep the added cost small relative to DINO/DA-V2. The exact cost must be measured; target overhead <0.1–0.3 s for the <=10-view service budget.

**Implementation burden / licensing.** This is a local arithmetic change with no new external model or license dependency. It is preferable to adding a heavier foundation model if H3 is supported.

**Execution status.** No Spark/GPU experiment was executed. No behavior-changing patch was made in this iteration; the finding comes from direct source-code audit. The proposed A/B/C/D test is unexecuted.

**Next experiment.** Add diagnostics first: per-Gaussian `visible_views > valid_views` count/max, per-view overlap between positive-affected and negative-affected Gaussian sets, and a counter for negatives that would fail the same depth-consistency test. This instrumentation can establish whether the semantic bug is materially active before changing aggregation behavior.


## 22:00 — Geometry-aware view selection: image count is not the same variable as geometric coverage

**Question.** The current 5/15/30/50 experiments randomly subsample post-change cameras. If the deployment budget is <=10 images, can we improve useful change support by selecting complementary views rather than increasing raw image count?

**Code fact.** In `CLSplatsTrainer.update_cameras()`, when `0 < train.num_change_views < total_views`, the current implementation uses Python `Random(view_sample_seed).sample(...)` and then sorts the selected indices. Thus the sparse-view experiments vary the *number* and seed of cameras but do not optimize baseline, changed-region visibility, angular diversity, or prior observation count. This makes random-subset variance a potential confounder in the Coverage hypothesis: a bad 5-view subset can have redundant viewpoints, while a good 5-view subset may cover the changed region much better.

**Literature.** Chen et al., *Coverage Optimization for Camera View Selection* (CVPR 2026, arXiv:2604.05259) derive a lightweight view-selection surrogate from Fisher information and show that favoring geometry insufficiently observed by previous cameras can outperform random and heavier information-theoretic baselines. Their COVER metric avoids expensive transmittance estimation and only needs Gaussian projection/coverage counting; the project page reports projection-based scoring that can be visualized at ~85 FPS, although their full-dataset selection benchmark is not directly our <=10-view latency setting. CoMapGS (Jang & Pérez-Pellitero, CVPR 2025) independently uses covisibility maps to identify underrepresented sparse regions and applies covisibility-aware supervision. SA-ResGS (Kim et al., 2026, arXiv:2601.03024) further reports that sparse/wide-baseline 3DGS benefits from physically grounded coverage-aware next-best-view selection. These methods address full reconstruction rather than local change updating, so transfer must be tested rather than assumed.

**Transfer to CL-Splats.** We already possess the *old* 3DGS before the physical change, so unlike cold-start NBV we have a strong geometric proxy for cheap candidate scoring. After one or two seed images produce a tentative changed 3D support set \(G_c\), candidate camera \(v\) can be scored by the amount of currently under-observed changed support it sees:
\[
C(g)=\sum_{u\in S}V(g,u),\qquad
\mathrm{score}(v)=\sum_{g\in G_c}V(g,v)\,w(C(g)) - \lambda R(v,S),
\]
where \(V(g,v)\) is projected/depth-consistent visibility in the old GS, \(w(C)=1/(C+\epsilon)\) or \(e^{-C/\tau}\) prioritizes under-covered Gaussians, and \(R\) penalizes redundant cameras (e.g. similar viewing direction/baseline). Greedy selection repeats until K<=10. This is a local set-cover approximation, not a new neural network.

A stronger objective can include triangulation conditioning. For changed support point \(g\), let \(\theta_{uvg}\) be the angle between rays from selected cameras \(u,v\). Reward complementary baselines with \(q(\theta)=\sin^2\theta\) while rejecting extreme occluded baselines. A practical score is
\[
\mathrm{score}(v)=\sum_{g\in G_c}V(g,v)\left[\alpha\,w(C(g))+\beta\max_{u\in S}q(\theta_{uvg})\right]-\lambda R(v,S).
\]
This explicitly separates *coverage* (is the changed surface observed?) from *conditioning* (are the observations geometrically complementary?).

**Hypothesis H4 (falsifiable).** For a fixed budget of 5 post-change images, geometry-aware selection from the same candidate pool will recover substantially more of the 50-view reference active support and improve changed-region reconstruction than random 5-view subsets. If true, the earlier 397-vs-7114 active-count gap partly reflects view selection, not an irreducible need for many images.

**Controlled test.** Using the existing 50-view candidate pool and old GS, compare at K=5: A=random seeds (>=20 seeds); B=farthest-pose/angular-diversity only; C=old-GS coverage greedy; D=coverage + baseline-conditioning. Keep DINO, DA-V2, lifter thresholds, and optimization iterations fixed. Primary pre-optimization metrics: active-set recall/precision against 50-view reference, *synthetic GT changed-support recall where available*, number of valid depth-aligned views, changed-support observation-count histogram, and pairwise ray-angle distribution. Reconstruction metrics at 100 iterations: changed-region PSNR/SSIM/LPIPS and held-out reprojection/depth error. Report median and worst-quartile over seeds, not only the best subset.

**Falsification / abandonment.** Reject view selection as a major lever if C/D fail to improve GT changed-support recall by at least ~15 percentage points over the random median, or if increased reference-mask recall is mostly false-positive support and does not improve changed-region quality. Also reject a method if scoring overhead or required capture protocol makes the <=10 s service target impractical.

**Latency.** This direction is attractive because selection can occur *before* expensive DINO/DA-V2 processing for all candidate images. Old-GS projection is cheap and can be restricted to a local ROI. If the service controls capture interactively, each next view can be recommended from a small discrete candidate set. For already-uploaded <=10 photos, the same score can select the best 3–5 for expensive processing. Target selection overhead: <0.1–0.3 s for local candidate Gaussians; measure rather than assume. The CVPR 2026 COVER paper's full-scene timing is not directly transferable, but its projection-only mechanism supports the plausibility of a lightweight implementation.

**Interaction with H1–H3.** This test should not precede the H3 visibility audit when interpreting current active masks, because the current aggregation semantics can distort apparent coverage. However, after fixing/diagnosing visibility, view selection is the cleanest way to test whether sparse-view failure is truly *geometric coverage* rather than noisy evidence. H2 also matters: a geometrically good view that fails DA-V2 metric alignment contributes no lifting evidence, so a deployable score should eventually include an empirical alignment-reliability term.

**Implementation / licensing.** The proposed score can be implemented independently with existing camera poses and old-GS geometry; no external model or code dependency is required. COVER's paper is useful for the principle and evaluation design, not as a required software dependency. Any repository license would still need verification before copying code.
