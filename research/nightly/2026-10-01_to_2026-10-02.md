## 18:00 — False-positive rejection via geometry-conditioned DINO evidence

**Question.** Can DINO false positives be reduced without sacrificing sparse-view recall or adding a heavy model?

**Code fact.** The current detector compares rendered-old and observed-new DINOv2 intermediate features with per-location cosine similarity, applies one threshold, and optionally dilates the binary mask. It does not explicitly test whether low similarity comes from physical change versus depth-boundary/occlusion/render misregistration. Multiview voting can reject random errors, but repeated boundary errors can survive.

**Literature.** CL-Splats uses DINOv2 masks, dilation, 3D voting, and localized optimization. Its ablation favors voting over an all-view requirement, so simply making min-positive-views very strict is not an attractive sparse-view fix. The paper also states that global illumination changes remain a limitation (Ackermann et al., ICCV 2025, arXiv:2506.21117).

**Hypothesis H1 (unverified).** A meaningful subset of false positives is concentrated at pixels that are geometrically unreliable for rendered-old versus observed-new comparison: depth discontinuities, occlusion/disocclusion boundaries, or small pose/render mismatch.

**Proposed diagnostic.** Log soft DINO evidence s_dino = clamp((tau-cosine)/margin,0,1) and rendered-depth edge reliability r_edge = exp(-abs(grad(D_render))/sigma). Initially do not reject edge pixels. Test whether FP pixels have larger depth-gradient magnitude than TP pixels. If separation exists, test soft positive evidence e_pos = s_dino * r_edge instead of equal binary votes.

**Quantitative test.** On Blender before/after data, record DINO cosine, current decision, rendered-depth gradient, distance to depth discontinuity, and changed/unchanged reference label. Compare current DINO, hard edge rejection, and soft edge weighting at matched recall. Metrics: pixel precision/recall/F1/IoU, downstream active-Gaussian precision/recall, changed-region PSNR, and latency.

**Falsification.** Reject H1 if FP and TP depth-gradient distributions overlap strongly and geometry confidence cannot improve precision at matched recall.

**Why before threshold sweeps.** Threshold/dilation/min-positive sweeps only move the operating point. This diagnostic tests a causal explanation and costs little because rendered depth already exists.

**Coverage/Convergence implication.** If precision improves at maintained recall, part of the apparent sparse-view problem may be evidence quality rather than viewpoint count. If not, view geometry remains a stronger candidate. Coverage and Convergence remain working hypotheses.

**Execution status.** No remote GPU experiment was executed by this automation. No behavior-changing source patch was made in this iteration.

**Next.** Instrument FP/TP DINO cosine and rendered-depth-gradient distributions on the test branch; only then consider confidence-weighted multiview voting.


## 19:00 — Depth lifting bottleneck: alignment support, not depth-network accuracy, may dominate sparse-view failure

**Question.** In the <=10-view regime, is the Depth Anything V2 stage failing mainly because monocular depth is inaccurate, or because CL-Splats cannot robustly align relative depth to the existing GS metric frame from the available pixels?

**Measured evidence.** In the user's earlier CL-Splats run, depth alignment failed for 58/75 views. This is unusually high even with many input views, so "more views" alone cannot be assumed to solve lifting. The 5-view deployment target makes per-view alignment failure much more consequential: losing 2–3 views can collapse multiview support even if DINO change detection itself is correct.

**Code/config facts.** Current configuration uses `depth-anything/Depth-Anything-V2-Small-hf`; downstream lifting then applies k-NN/local-radius/depth-consistency gates. The inspected lifter path from the prior debugging session calls `align_relative_depth(mono, rendered_depth, change_mask, min_pixels=200)`. Thus metricization is a separate estimation problem after monocular inference. This matters because DA-V2's general relative-depth model is explicitly scale/shift ambiguous; improving the network does not automatically remove alignment failure.

**Literature.** Depth Anything V2 (Yang et al., 2024, arXiv:2406.09414) emphasizes robust relative depth and provides separately fine-tuned metric models. Depth Pro (Bochkovskii et al., 2024, arXiv:2410.02073) predicts metric depth directly and reports ~0.3 s for a 2.25-MP map on its reference GPU, showing that metric monocular depth can be fast, but domain transfer remains an assumption. UniDepthV2 (Piccinelli et al., 2025, arXiv:2502.20110) predicts metric 3D and an uncertainty output, which is attractive for confidence-weighted lifting but is a heavier replacement. Most directly relevant, Reliability-Aware Monocular Depth Supervision for Sparse-View Neural Reconstruction (Chu et al., 2026, arXiv:2607.02554) aligns DA-V2 per-image scale/shift to sparse metric anchors and finds that selectively using reliable depth regions matters more than globally supervising all pixels; this supports testing anchor quality before replacing DA-V2.

**Causal hypothesis H2 (unverified).** A major part of sparse-view lifting failure is ill-conditioned scale/shift estimation caused by too few, too spatially concentrated, or contaminated alignment pixels, rather than DA-V2 inference error itself. If the alignment support is selected from/around a change mask, changed/occluded pixels can further contaminate the fit.

For relative prediction \(d_r(p)\) and rendered metric depth \(d_g(p)\), estimate
\[
(a^*,b^*)=\arg\min_{a,b}\sum_{p\in A} w_p\,\rho(a d_r(p)+b-d_g(p)),
\]
where \(A\) should be reliable unchanged/visible anchors, \(\rho\) is a robust loss (Huber/Tukey), and \(w_p\) downweights depth edges, low rendered opacity, suspected change, and high monocular uncertainty. This is preferable to treating every available alignment pixel equally.

**Important distinction from the 18:00 hypothesis.** The 18:00 run asked whether geometry uncertainty explains DINO false positives. H2 instead asks whether geometry uncertainty corrupts *metric depth alignment after detection*. Both can be true, but they are experimentally separable.

**Minimal diagnostic before changing models.** For every view log: number of candidate anchors; number/inlier ratio after robust fit; spatial coverage of anchors (occupied image-grid cells); fitted scale \(a\), shift \(b\); residual median/MAD and p90; failure reason; and whether the view later contributes positive/negative 3D votes. Compare successful versus failed alignment views. Also recompute alignment with (A) current anchors, (B) unchanged-mask-only anchors, (C) unchanged + depth-edge exclusion, and (D) robust IRLS/RANSAC-style fit.

**Falsifiable prediction.** If H2 is correct, alignment success and downstream active-Gaussian recall should correlate more strongly with anchor inlier count/spatial spread and residual MAD than with raw image count. Robust unchanged-region alignment should recover a substantial fraction of currently skipped views without replacing DA-V2.

**Failure criterion.** Abandon H2 as a primary bottleneck if failed views already have abundant, spatially distributed low-residual anchors, or if robust alignment increases accepted views but does not improve active-Gaussian precision/recall or changed-region reconstruction. In that case test monocular-depth domain error / occlusion geometry directly, or benchmark a metric model such as Depth Pro/UniDepthV2.

**Latency.** Robust affine fitting over <=1024 anchors is negligible relative to DA-V2 inference (typically milliseconds on GPU/CPU for IRLS/RANSAC-scale operations). Reliability masks from existing rendered depth/opacity are also cheap. Therefore this intervention is compatible with the <=10 s target and is preferable as the next test to swapping in a heavier depth foundation model.

**License/deployment note.** Do not switch models on paper performance alone; verify code/weight licenses separately before any industrial recommendation. This iteration makes no commercial-use claim for Depth Pro or UniDepthV2.

**Execution status.** No Spark/GPU experiment was executed by this automation. No behavior-changing source patch was made. The proposed diagnostic is unexecuted.

**Next experiment.** Instrument alignment conditioning and failure reasons first. If H2 survives, implement robust unchanged-region scale/shift fitting and compare 5-view active-set recall, skipped-view count, changed-region PSNR/SSIM/LPIPS, prepare time, and total latency against the current aligner. This should precede a DA-V2→metric-depth model replacement.
